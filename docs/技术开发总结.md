# 多模态企业级智能体系统 - 技术开发总结文档

## 一、项目概况

本项目从零构建了一套"多模态、强记忆、会思考、能执行"的企业级智能体系统。系统采用 Python + FastAPI + LangGraph 为核心技术栈，以通义千问作为主模型，支持文本/图像/语音/文件多模态交互，具备自主任务规划、分层记忆、工具调用、人机协同决策能力。

---

## 二、技术架构

系统采用六层分层架构，各层通过标准化接口解耦通信：

```
┌─────────────────────────────────────────────────────────┐
│ 统一接入/API网关层 (FastAPI + 限流 + 多租户中间件)        │
├─────────────────────────────────────────────────────────┤
│ 多模态交互层 (模态路由器 + 视觉/语音/文件处理器)         │
├─────────────────────────────────────────────────────────┤
│ 核心编排层 (LangGraph状态机 + ReAct循环 + 任务规划)      │
├─────────────────────────────────────────────────────────┤
│ 领域服务层 (行政办公/财务 场景规则 + 场景扩展框架)       │
├─────────────────────────────────────────────────────────┤
│ 工具集成层 (工具注册中心 + 安全治理 + 协议适配)          │
├─────────────────────────────────────────────────────────┤
│ 数据/记忆存储层 (PostgreSQL + Milvus + Neo4j + MinIO)    │
└─────────────────────────────────────────────────────────┘
```

## 五、核心模块详解

### 5.1 API网关层 (`services/gateway/`)

**职责**：系统唯一流量入口，统一处理请求路由、安全防护、流量治理。

**核心文件**：
- `__init__.py` - FastAPI应用工厂，集成中间件和路由
- `routes_chat.py` - 对话API（/chat/completions + /chat/upload）
- `middleware.py` - 多租户中间件（从Header/JWT/Param提取tenant_id）+ 限流中间件（200次/分钟）
- `tracing.py` - OpenTelemetry链路追踪集成

**API端点**：
- `GET /health` - 健康检查
- `GET /api/v1/ready` - 就绪探针
- `POST /api/v1/auth/token` - 用户登录获取JWT
- `POST /api/v1/chat/completions` - 文本对话
- `POST /api/v1/chat/upload` - 文件/图像/音频上传

### 5.2 多模态交互层 (`services/multimodal/`)

**职责**：接收用户的多模态输入，转换为结构化数据交给编排层。

**核心组件**：
- `router.py` - 模态路由器：根据MIME类型或文件扩展名自动识别模态（text/image/audio/video/file），分发到对应处理器
- `vision/processor.py` - 视觉处理器：调用千问VL模型理解图片，提取文字/表格/数据
- `speech/processor.py` - 语音处理器：调用Whisper进行语音转写 + Edge TTS语音合成
- `file/processor.py` - 文件处理器：支持PDF(PyPDF2)、Word(python-docx)、Excel(openpyxl)、CSV、TXT解析

**设计特点**：处理器之间完全解耦，新增模态只需实现`BaseProcessor`并注册到路由器。

### 5.3 核心编排层 (`services/orchestrator/`)

**职责**：系统大脑——任务规划、执行编排、记忆管理、模型调用。

**核心组件**：

#### LLM路由器 (`llm_router.py`)
- 支持三个Provider：Qwen（主）、OpenAI（备用）、DeepSeek（备用）
- 按能力类型路由：REASONING / VISION / GENERAL / CODE
- 所有Provider使用OpenAI兼容协议，切换零成本

#### LangGraph状态机 (`graph.py` + `state.py`)
- 五个节点：plan → check_confirmation → execute → respond → END
- 条件边实现动态路由：无子任务直接回复、高风险进审批、正常进执行
- 最大迭代次数保护（防止无限循环）

#### 任务规划引擎 (`planner/engine.py`)
- 基于ReAct框架：Thought → Action → Observation循环
- 规划阶段：将用户目标拆解为子任务，确定依赖关系、工具、风险等级
- 执行阶段：每步根据工具返回结果动态调整后续路径
- 输出JSON格式化的执行计划

#### 分层记忆系统 (`memory/`)

| 组件 | 文件 | 功能 |
|------|------|------|
| 记忆管理器 | `manager.py` | 三级架构统一入口：工作记忆(内存) + 短期(向量库,7天TTL) + 长期(向量+图谱) |
| 向量存储 | `vector_store.py` | 对接Milvus，千问embedding(1024维)，支持过滤检索 |
| 图谱存储 | `graph_store.py` | 对接Neo4j，存储用户-记忆关系，支持关系路径搜索 |
| GraphRAG | `graph_rag.py` | 混合检索：向量相似度(权重0.6) + 图谱关系(权重0.4)，支持子图扩展 |
| 生命周期 | `lifecycle.py` | 重要性评分(时间衰减+频率+近期访问)、淘汰策略、短期→长期提升 |
| 记忆进化 | `evolution.py` | 任务经验自动提取、用户偏好模式分析 |

#### 工具编排执行器 (`executor/`)
- `human_in_loop.py` - 人机协同：LOW自动执行 / MEDIUM执行+审计 / HIGH需人工审批
- `workflow_engine.py` - 低代码工作流引擎：支持可视化编排、条件分支、并行节点

#### 模型效果评测 (`evaluation.py`)
- 用户反馈收集（positive/negative/neutral）
- 准确率报告生成
- 优化建议输出
- 评测数据集导出（供prompt优化/fine-tune使用）

### 5.4 领域服务层 (`services/domain/`)

**职责**：封装行业业务规则，隔离技术层与业务层。

**已实现场景**：

#### 行政办公场景 (`office_tools.py`)
- `calendar_query` - 日程查询
- `meeting_room_book` - 会议室预订
- `approval_submit` - 审批提交（报销/请假/采购）
- `notification_send` - IM消息通知

#### 业务规则引擎 (`business_rules.py`)
- 会议室预订校验（时长上限4h、容量上限50人）
- 报销规则（500元以下免审批、5万上限）
- 通知免打扰时段（22:00-08:00）
- 日程冲突自动建议可用时段

#### 场景扩展框架 (`scenario_framework.py`)
- `DomainScenario` 抽象基类：定义标准扩展接口
- `ScenarioRegistry` 场景注册中心：统一管理
- 已实现示例：财务场景（发票验真、报销单生成）
- 新场景接入只需继承基类、注册工具和规则

### 5.5 工具集成层 (`services/tooling/`)

**核心组件**：
- `registry/tool_registry.py` - 工具注册中心：注册/注销/查询/执行，支持超时控制和重试
- `registry/builtin_tools.py` - 内置工具：计算器、网络搜索、数据查询、日期时间
- `governance/security.py` - 安全治理：Payload检测（危险模式拦截）、SSRF防护、权限校验、审计日志
- `governance/compliance.py` - 合规检查：21项企业安全检查清单、自动生成合规报告

**工具接口标准**：所有工具继承`BaseTool`，实现`execute(parameters) -> dict`方法。

### 5.6 认证授权 (`services/auth/`)

- JWT令牌签发/验证（HS256，30分钟过期）
- bcrypt密码哈希
- OAuth2.0 Bearer Token认证
- 角色权限校验（admin/user）
- 内置演示用户：admin/admin123、demo/demo123

## 六、数据库设计

共7张核心表（PostgreSQL），通过Alembic管理迁移：

| 表名 | 说明 | 关键字段 |
|------|------|----------|
| `tenants` | 租户 | id, name, config, is_active |
| `users` | 用户 | id, tenant_id(FK), username, hashed_password, roles |
| `conversations` | 会话 | id, tenant_id(FK), user_id(FK), title |
| `messages` | 消息 | id, conversation_id(FK), role, content, modalities |
| `tasks` | 任务 | id, conversation_id(FK), user_goal, plan, status, risk_level |
| `tool_calls` | 工具调用 | id, task_id(FK), tool_name, parameters, result, duration_ms |
| `memories` | 记忆 | id, tenant_id(FK), user_id(FK), memory_type, content, importance_score |

全部表带 `tenant_id` 索引，强制多租户数据隔离。

## 七、运维与监控

### Prometheus 指标（`infra/monitoring/metrics.py`）
- 业务：任务总数/成功率、任务耗时分布、活跃会话数
- 模型：LLM调用次数/延迟/Token消耗
- 工具：工具调用成功率/延迟
- 记忆：检索耗时、存储容量
- 安全：安全事件数、待审批积压

### 告警规则（`infra/monitoring/alert_rules.yml`）
- 任务失败率 > 5% → Critical
- LLM调用失败率 > 10% → Critical
- P95任务耗时 > 10s → Warning
- 安全事件突增 → Critical
- 待审批积压 > 10 → Warning

### 部署配置
- Dockerfile：Python 3.11 slim镜像
- K8s Deployment：2-10副本 HPA（CPU 70%/Memory 80%触发扩容）
- Ingress + Canary：支持灰度发布（10%流量切换）

## 八、如何启动项目

### 本地开发

```bash
# 1. 克隆项目后进入目录
cd agent

# 2. 启动基础设施（PostgreSQL + Redis + Milvus + Neo4j + MinIO）
docker compose up -d

# 3. 安装Python依赖
pip install -e ".[dev,multimodal]"

# 4. 配置环境变量
cp .env.example .env
# 编辑 .env，填入 QWEN_API_KEY=sk-xxxxxxxx

# 5. 执行数据库迁移
alembic upgrade head

# 6. 启动API服务
python -m services.gateway.main
# 服务运行在 http://localhost:8000

# 7. 打开前端Demo
# 浏览器打开 frontend/index.html
```

### 运行测试

```bash
# 单元测试
pytest tests/unit/ -v

# 带覆盖率
pytest tests/unit/ -v --cov=services --cov=shared

# 压测（需安装locust）
locust -f tests/e2e/locustfile.py --host=http://localhost:8000
```

### Docker部署

```bash
docker build -t enterprise-agent:latest -f infra/docker/Dockerfile .
docker run -p 8000:8000 --env-file .env enterprise-agent:latest
```

## 九、核心数据流

```
用户输入（文本/图片/语音/文件）
    ↓
[API网关] 认证 → 多租户识别 → 限流
    ↓
[模态路由器] 识别模态类型 → 分发到对应处理器
    ↓
[处理器] 转换为结构化数据（文本描述/转写文本/文件内容）
    ↓
[LangGraph状态机] 入口
    ↓
[规划节点] 检索历史记忆 → LLM生成任务计划 → 风险评估
    ↓
[确认节点] 高风险? → 人工审批 / 低风险 → 直接执行
    ↓
[执行节点] ReAct循环: Thought → 选工具 → 调用 → 观察结果 → 继续/完成
    ↓
[响应节点] 基于执行结果生成最终回复
    ↓
[记忆存储] 异步写入：工作记忆 + 短期记忆 + 长期记忆（含经验提取）
    ↓
[返回用户] 结构化响应
```
